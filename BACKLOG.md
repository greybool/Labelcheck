# BACKLOG — отложенные идеи

Правило: новые идеи попадают сюда, а не в текущий спринт (защита от
скоуп-крипа, см. `docs/TZ-LABELCHECK.md` §4.3 и раздел 9 ТЗ). Пункт берётся
в работу только решением владельца проекта и только из буферных дней.
Формат: что — зачем — откуда возникло.

## Retrieval / токенизация

- **Е-коды с пробелом («Е 635»)** — токенизатор BM25 не склеивает
  пробельную форму с «Е635», такой запрос теряет точность. Возникло при
  анализе реальных упаковок (День 2–3).
- **Слияние part-частей пунктов в матчере** — сейчас части разрезанного
  пункта приложения засчитываются консервативно (строго по chunk_id);
  слияние подняло бы Hit@K на длинных пунктах. Из EVALUATION.md (День 3).

## Аспекты / чек-лист

- **Аспект «изображения на упаковке»** (022 ч.4.12 п.8–9): нельзя изображать
  продукты, которых нет в составе; изображение готового блюда — только со
  словами «вариант приготовленного блюда». Отложено Днём 5: требует
  распознавания СОДЕРЖАНИЯ картинок (не текста) — новый класс vision-задач
  с риском ложных срабатываний. (День 5.)
- **Замер высоты шрифта в мм по PDF-макету** — физические размеры страницы
  макета известны, высоту литер можно мерить по рендеру; закрыл бы аспект 17
  (2 мм / 0,8 мм из 022 ч.4.12 п.1) без ручной проверки. (День 5.)
- **Категория children (детское питание)** — 034 п.126, 040 п.75, детские
  нормы прил.2 к 022: отдельная ветка category_regulations, если в
  ассортименте появится детская заморозка. (День 5.)
- **Запрос аспекта 21 разбить на отдельные клеймы** — CHEAP-модель при
  переформулировке склеила примеры («низкокалорийный источник белка без
  сахара») в одну фразу; безвредно (оригинал всегда в слиянии), но запросы
  точнее по одному клейму. (День 5, смоук rewriting.)

## Vision-модуль

- **Кросс-языковая сверка составов RU/EN/KK** — на реальных макетах составы
  на разных языках расходятся (добавки, присутствующие только в одном
  языке) — это потенциальные нарушения, которые сейчас не ловятся. Плюс
  замечено: на языках вне скоупа модель может тихо заменить термин
  смысловым синонимом — сверка должна учитывать это. (Дни 1 и 4.)
- **Кир/лат микс внутри слова в текстовом слое** («hалейте» с латинской h) —
  сверка со слоем не сшивает такие слова с vision-текстом, даёт ложное
  «непрочитано» в coverage. Нормализовать гомоглифы. (День 4.)
- **Многостраничные макеты** — читается только первая страница
  (`page_index=0`); `page_count()` уже есть. Нужен цикл по страницам
  и объединение JSON. (День 4.)
- **Retry/backoff на ошибки API** — vision.py падает исключением на сетевой
  ошибке или rate-limit; для батч-прогонов (evaluation Дня 8) нужен
  повтор с паузой. (День 4.)
- **Кэш vision-результатов по SHA256 PDF** — повторный прогон того же
  макета стоит те же $0.06–0.09; пломба source_sha256 уже в meta,
  осталось смотреть в data/layouts/ перед вызовами. Пригодится UI (День 9)
  и evaluation (День 8). (День 4.)
- **Responses API вместо chat.completions** — рекомендации OpenAI для
  документов (`text.verbosity=high` для дословности, `detail=original`)
  доступны только там; сейчас читаем через chat.completions с detail=high.
  Оценить, даёт ли переход прирост качества чтения. (День 4.)
- **Детерминизация обзора (seed)** — число регионов и kind-метки гуляют
  между прогонами; параметр seed мог бы стабилизировать прогоны для
  сравнения конфигураций. (День 4.)
- **Порог-предупреждение для coverage** — сейчас доля покрытия слоя только
  сохраняется и печатается; ниже порога (например 90%) можно поднимать
  явный флаг неполноты в JSON. (День 4.)
- **Текстовый слой как черновик чтению** — отвергнуто из-за риска якорения
  на невидимый/устаревший текст под кривыми; вернуться, только если
  качество чтения макетов в кривых просядет. (День 4, решение владельца.)
- **kind_markers для product_name** — полнота названия продукта сейчас
  проверяется только kind-меткой (сигнальных слов у названия нет);
  подумать над эвристикой (крупнейший кегль на лицевой панели). (День 4.)

## Проверки без LLM

- **Арифметика энергетической ценности** — на одном из тестовых макетов
  кДж/ккал не сходятся с БЖУ; формула проверяется без LLM. (День 1.)
- **Контрольная цифра EAN-13** — штрихкод уже читается vision-модулем
  с цифрами; валидация контрольной цифры — чистая арифметика. (День 1.)
